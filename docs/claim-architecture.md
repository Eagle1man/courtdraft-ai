# Архитектура генерации иска (детерминированный путь)

**Версия:** 1.0
**Дата:** 24.11.2026
**Путь:** `docs/claim-architecture.md`

## 1. Цель

Детерминированная генерация искового заявления из паспорта дела без вызова
языковой модели. Весь текст собирается правилами: LLM не участвует ни в
одном из 15 этапов проверки.

## 3. Модули

### 3.1. `app/ingestion/passport.py`
Pydantic-модель `CasePassport` для схемы `case-passport/3.1`.
- Структурная валидация — pydantic
- Арифметические инварианты (И-1…И-14) — `validate_invariants()`
- Поиск паспорта в материалах дела: `find_passport_in_documents()`

### 3.2. `app/money.py` и `app/money_words.py`
Единый канон денег: целые копейки, четыре прохода разбора,
единый формат вывода (`format_rub`).

### 3.3. `app/textnorm.py`
- `normalize()` — канонический вид текста
- `broken_numbers()` — детект разрывов чисел
- `broken_words()` — эвристика разрыва слов

### 3.4. `app/drafting/claim_model.py`
`ClaimModel` — замороженная dataclass-модель иска:
- 30+ полей (стороны, суммы, даты, требования, приложения)
- Сборка из паспорта: `from_passport(data)`
- Инварианты: `validate()` (И-1, И-3, И-4, И-10…)
- Правка = замена слота: `with_court(value)`

### 3.5. `app/drafting/claim_render.py`
`render_claim(model)` — чистая функция:
- 15 блоков: шапка, стороны, цена, наименование, 4 факта,
  правовое обоснование, преамбула, просительная часть, итог,
  приложения, подпись
- Побайтово воспроизводимый текст
- `RenderedClaim.p0_count` — число разрывов чисел + служебных фраз

### 3.6. `app/verification/claim_model_checks.py`
15 кросс-проверок X01–X15:
| Код | Проверка | Severity |
|-----|----------|----------|
| X01 | Цена иска = долг + проценты | P0 |
| X02 | Итог = цена + пошлина | P0 |
| X03 | Пошлина = уплаченная | P0 |
| X04 | Период процентов точный | P0 |
| X05 | Шапка суда ×1 | P0 |
| X06 | Арифметика расчёта | P0 |
| X07 | Пошлина не в цене | P0 |
| X08 | Приложения: 7 на 9 | P0 |
| X09 | Подсудность | P1 |
| X10 | Исковая давность | P1 |
| X11 | Инверсия ролей | P0 |
| X12 | Разрывы чисел | P0 |
| X13 | Обязательные слоты | P0/P1 |
| X14 | Служебный текст | P0 |
| X15 | Объём 3200–4500 | P1 |

### 3.7. `app/verification/deviations.py`
Журнал расхождений: X09 (подсудность), FEE (госпошлина),
INT_CLOSURE (приведение процентов), INT_PERIOD (конец периода).

### 3.8. `app/services/export_gate.py`
- `assert_export_allowed(p0_count, is_stale, mode)`:
  блокирует выгрузку при P0 > 0 или устаревшем отчёте.
- `mode="draft"` — разрешено всегда; `mode="final"` — с проверками.

### 3.9. `app/fees.py`
Расчёт госпошлины по редакции НК РФ на дату подачи иска.

## 4. Временные характеристики

| Операция | Время | Цель |
|----------|-------|------|
| `ClaimModel.from_passport()` | < 5 ms | < 50 ms |
| `render_claim()` | < 10 ms | < 50 ms |
| `verify_claim_model()` (15 checks) | < 30 ms | < 100 ms |
| `build_deviations()` | < 10 ms | < 50 ms |
| **Полный цикл без LLM** | **< 60 ms** | **< 1 с** |
| DOCX-экспорт (python-docx) | ~200 ms | < 1 с |
| **Итого на запрос** | **< 300 ms** | **< 1 с** |

## 5. Без LLM

Ни одна из вышеперечисленных операций не обращается к языковой модели.
Текст иска — детерминированный, побайтово воспроизводимый:

```python
model = ClaimModel.from_passport(passport)
text = render_claim(model).text
# text всегда одинаков для одного passport
```

Проверки X01–X15 также детерминированные: сравнивают модель,
отрендеренный текст и паспорт. LLM не нужна.

## 6. Расширение (CLEAN-режим)

Режим `CLEAN` включает пересчёт по фактическим ставкам ЦБ
(`app/verification/interest.py::closure()`) и синхронный пересчёт
`price`/`total` во всех документах. Детерминированность сохраняется.
