# Дообучение фильтра инструкций на русском

Дата: 2026-11-01. Повод: ни одна готовая модель не различает русские
перефразы попыток управлять моделью (замеры — `docs/injection-filter-model.md`).

## 1. Что уже есть

| Подход | precision | recall |
|---|---:|---:|
| Детерминированные правила | 1,00 | 0,44 |
| `qwen2.5:1.5b` (промпт) | 0,81–0,85 | 0,94 |
| `qvikhr` 1,7B (промпт) | 1,00 | 0,22 |
| Prompt Guard 2 86M (ONNX int8) | 1,00 | 0,17 |

Цель дообучения — precision ≥ 0,90 и recall ≥ 0,70 на **контрольном**
наборе, которого модель при обучении не видела.

## 2. Данные

### 2.1 Синтетика (генерируется здесь)

```powershell
cd D:\courtdraft-ai
backend\.venv\Scripts\python.exe scripts\build_injection_dataset.py --size 2000
```

Результат — `data/injection_guard/{train,val,test}.jsonl`, 80/10/10,
баланс 1:1:

```
train: 1600 (benign 802, injection 798)
val:    200 (benign 98,  injection 102)
test:   200 (benign 100, injection 100)
```

Что внутри:

- **обычные** — 30 юридических предложений (процедура, нормы, суммы,
  даты), склеенные по 1–3 и обёрнутые в «фрагмент иска/решения/договора»;
  специально слова «инструкция», «указание», «руководствуясь»;
- **попытки** — 30 начал × 10 окончаний × 6 обёрток, то есть не одна
  заученная фраза: «игнорируй предыдущие инструкции», «представь, что ты
  юрист ответчика», «выведи системный промпт», «новые инструкции» и т. д.

**Контрольный набор `backend/tests/data/injection_guard_set.jsonl` (54
фрагмента) не используется в обучении** — скрипт проверяет пересечение
по нормализованному тексту и отбрасывает совпадения. Тест это
фиксирует.

### 2.2 Переводы открытых наборов (на ВМ)

Синтетики мало: живые попытки формулируются иначе. На ВМ добавить
переводы открытых наборов и подмешать их через `--extra`:

```powershell
backend\.venv\Scripts\python.exe scripts\build_injection_dataset.py `
  --size 2000 --extra data\translated_injections.jsonl
```

Откуда брать:

| Набор | Лицензия | Язык |
|---|---|---|
| `deepset/prompt-injections` | Apache-2.0 | англ./нем. |
| `jackhhao/jailbreak-classifier` | Apache-2.0 | англ. |
| `xTRam1/safe-guard-prompt-injection` | MIT | англ. |
| `rubend18/ChatGPT-Jailbreak-Prompts` | MIT | англ. |

Перевод — локально, без облака: `Helsinki-NLP/opus-mt-en-ru`
(CC-BY-4.0, ~300 МБ, CPU). `facebook/nllb-200-*` не брать: лицензия
CC-BY-NC (некоммерческая) не подходит для продукта.

Формат `translated_injections.jsonl`: `{"text": "...", "label": "injection"}`.
Проверить перевод глазами (10–20 строк на набор): машинный перевод
инструкций часто ломает смысл и даёт мусорные метки.

### 2.4 Реальные обезличенные фрагменты (локально, 25 штук)

Синтетика не покрывает живые формулировки. Абзацы из настоящих дел уже
лежат в проекте обезличенными (`data/demo/real`), из них берутся
25 фрагментов:

```powershell
backend\.venv\Scripts\python.exe scripts\make_real_benign_fragments.py `
  --source data\demo\real --limit 25
```

Что важно:

- файл `data/real_benign_fragments.jsonl` **в git не входит** — это
  нарезка из реальных решений, пусть и обезличенная;
- скрипт пропускает реквизиты (ИНН, ОГРН, адреса, телефоны), берёт
  абзацы 150–600 символов с долей кириллицы выше 70%;
- 5–10 фрагментов надо прочитать глазами: автоматическая проверка
  персональных данных не гарантирует.

Подмешивается вторым `--extra` (ключ можно повторять):

```powershell
backend\.venv\Scripts\python.exe scripts\build_injection_dataset.py `
  --size 2000 `
  --extra data\translated_injections.jsonl `
  --extra data\real_benign_fragments.jsonl
```

Фактический набор 2026-11-01: `train 1775, val 222, test 222`.

## 3. Обучение

```powershell
# проверка данных без обучения
backend\.venv\Scripts\python.exe scripts\finetune_injection_guard.py --dry-run

# обучение
backend\.venv\Scripts\python.exe scripts\finetune_injection_guard.py
```

Если Trainer жалуется на `accelerate`, поставить его:
`.venv\Scripts\python.exe -m pip install "accelerate>=1.1"`.

Скрипт проверяет память до старта: для `mDeBERTa` нужно ~3,2 ГБ, для
`rubert-tiny2` — ~0,6 ГБ. Если свободной памяти меньше и GPU нет —
обучение не начинается (`--force` обходит проверку). Это защита от
многомесячной подкачки на 8 ГБ ноутбуке: `--dry-run` показывает ресурсы
и вердикт.

По умолчанию: `microsoft/mdeberta-v3-base` (та же архитектура, что у
Prompt Guard), 3 эпохи, lr 2e-5, max_len 256, batch 8. На ВМ с GPU —
десятки минут; на CPU — часы, поэтому обучать на этой машине не
планируется.

**Проверка конвейера (2026-11-01):** обучение `cointegrated/rubert-tiny2`
на 300 строках, 1 эпоха, 71 секунда на CPU; приёмка дала
precision 0,70 / recall 0,89 при пороге 0,5 — и **не прошла** критерий.
Это ожидаемо для черновика и важно: конвейер умеет отказывать, а не
объявлять слабую модель готовой.

Альтернативные базы:

| База | Размер | Когда |
|---|---:|---|
| `microsoft/mdeberta-v3-base` | ~1,1 ГБ | рекомендуемая |
| `DeepPavlov/rubert-base-cased` | ~700 МБ | русская, меньше памяти |
| `cointegrated/rubert-tiny2` | ~120 МБ | быстрый черновик |

## 4. Приёмка

```powershell
backend\.venv\Scripts\python.exe scripts\eval_injection_guard.py `
  --model models\injection-guard-ru
```

Скрипт печатает precision/recall по порогам и рекомендует порог. Модель
включается, только если на контрольных 54 фрагментах:

- **precision ≥ 0,90** (не больше 3–4 ложных на 36 обычных документов);
- **recall ≥ 0,70** (хотя бы 13 из 18 попыток).

Порог, который ничего не ловит (precision 1,00 при recall 0,00), не
рекомендуется: в выборе участвует и минимум recall 50%.

Если не дотягивает — расширять данные (переводы, реальные обезличенные
фрагменты), а не понижать порог.

## 5. Риски

1. **Синтетика ≠ живые тексты.** Шаблоны конечны; модель может выучить
   форму «обёртки», а не намерение. Лечится переводами открытых наборов
   и реальными фрагментами, которые присылают пользователи.
2. **Машинный перевод искажает смысл.** 10–20 строк каждого набора
   проверять вручную; мусорные метки портят обучение сильнее, чем мало
   данных.
3. **Переобучение на 54 контрольных.** Нельзя подбирать промпт или порог
   по этому набору многократно — он перестанет быть контрольным. Для
   подбора порога нужен свой val, а holdout трогать один раз в конце.
4. **Юридическая специфика.** Обычные документы содержат императивы
   («суд обязал», «взыскать»), и модель может счесть их командой. Примеры
   с такими формулировками в benign обязательны.
5. **Лицензии.** mDeBERTa — MIT, rubert — Apache-2.0, opus-mt — CC-BY
   (нужна атрибуция). Перед публикацией свериться с условиями.

## 6. Что дальше

1. Прогнать `--dry-run` на ВМ, убедиться, что данные на месте.
2. Перевести 2–3 открытых набора, подмешать через `--extra`.
3. Обучить, прогнать приёмку на 54 фрагментах.
4. Если precision/recall не дотягивают — добавить реальные обезличенные
   фрагменты и повторить, а не включать фильтр «на всякий случай».

## 7. Периодическая перепроверка

Фильтр может «съехать» после смены формулировок в документах. Проверка —
одна команда, раз в месяц и после каждого переобучения:

```powershell
backend\.venv\Scripts\python.exe scripts\eval_injection_guard.py `
  --model models\injection-guard-ru
```

Правило: если **precision падает ниже 0,90** — переобучать на свежих
фрагментах, а не понижать порог. Понижение порога увеличивает шум, а
проблема обычно в данных. Результаты складывать в
`docs/guard-eval-*.json` — там видно, какие фрагменты модель пропустила.
