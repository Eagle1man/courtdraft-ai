## Разрывы по приоритетам

### P0. Таблицы DOCX теряются

**ТЗ:** §4.3 «извлекать таблицы», §4.4 «не допускать потери информации
из таблиц».
**Сейчас:** `app/ingestion/extract.py:348` читает только абзацы;
таблицы считаются в метаданных и выбрасываются.
**Почему важно:** в таблицах — расчёты задолженности, графики платежей,
реквизиты. Их отсутствие прямо даёт `UNSUPPORTED_CLAIM` по суммам
(207 замечаний в тесте).
**Что делать:** извлечение таблиц через `python-docx` в текст с
разметкой строк/ячеек и ссылкой на таблицу. Docling — только если
замер покажет, что простого извлечения мало.
**Оценка:** 1–2 дня. Не требует новых зависимостей.

### P1. Реестр фактов (§9)

**Сейчас:** `evidence_items` — снимок пакета, перезаписывается целиком
(`replace_for_case`). Истории, статусов факта, ручных правок нет.
**Что делать:** таблицы `case_facts`, `case_fact_versions`,
`case_fact_evidence`; статусы из ТЗ (`extracted … needs_review`);
версионирование и автор изменения.
**Оценка:** 2 недели с миграциями и API.

### P1. Структурированное извлечение (§6)

**Сейчас:** пакет собирается эвристиками и разбором требований; модель
сразу пишет разделы.
**Что делать:** Pydantic-схемы (`CaseFact`, `CaseParticipant`,
`CaseAmount`, `CaseDate`, `CaseClaim`, `EvidenceReference`,
`Contradiction`, `MissingInformation`, `CaseRegistry`), Ollama Structured
Output по категориям, ограниченные повторы, `NEEDS_REVIEW` при провале.
**Оценка:** 2 недели; зависит от P0 (иначе суммы из таблиц не попадут).

### P1. Проверка цитат (§7.2)

**Сейчас:** `CITATION_DANGLING` и `MISSING_SOURCE` есть, но проверяется
наличие значения в материалах, а не цитаты в источнике.
**Что делать:** нормализация (пробелы, ё/е, дефисы), поиск цитаты в
тексте документа с `page`/`paragraph`, различение «нет совпадения» /
«смысловое подтверждение» / «противоречие» / «нет источника».
**Оценка:** 1 неделя.

### P2. Реестр противоречий (§7.4)

**Сейчас:** `CONTRADICTION` по тексту проекта.
**Что делать:** сравнение значений одного типа между документами

**Оценка:** 1–1,5 недели.

## Расхождения ТЗ с фактами (требуют решения)

1. **Vikhr-7B как основная модель.** В Ollama Vikhr помечен как
   `completion` (без chat-шаблона), сервис зовёт `/api/chat`. Нужен
   сравнительный прогон Vikhr / qwen2.5:7b / дообученный 1.5B — ТЗ это
   разрешает (§14, преамбула).
2. **8 ГБ ОЗУ.** 7B (4,7 ГБ) + bge-m3 (1,2) + Docling (1–2) + служба
   не помещаются одновременно. Нужен последовательный график:
   разбор → выгрузка модели → генерация.
3. **Docling и Python 3.14.** Локальный venv на 3.14; Docling
   поддерживает до 3.13 — ставить в отдельное окружение 3.12.
