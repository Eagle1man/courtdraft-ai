# Тест на ВМ: памятка участнику и администратору

Адрес системы: **http://10.19.20.20:8081/app**

Это тестовый стенд. Система формирует **проект** судебного акта.
Решение принимает человек; автоматического утверждения нет.

## Сценарий теста: два этапа

1. **Первое дело — все на быстрой модели.** Студент создаёт дело, указывает
   свой код участника (например, `S01`) и загружает материалы. Проект
   формируется за 3–4 минуты, все смотрят результат и обсуждают.
2. **Второе дело — сравнение моделей.** Перед вторым этапом администратор
   включает квоту: первым **5** делам достаётся Vikhr 7B, остальным —
   быстрая 1.5B. Студенты загружают второе дело и нажимают
   «Сформировать проект». Сильную модель ждать долго, поэтому можно
   закрыть страницу: сервер продолжит работу после занятия.
3. **Разбор.** Все материалы, проекты и отзывы выгружаются в
   `data/learning/` с разбивкой по коду участника и модели.

## Что делать участнику (3 шага)

1. **Выбрать дело.** Слева уже есть демонстрационное дело «2-456/2025».
   Можно создать своё: «+ Создать дело», заполнить номер, суд и **код
   участника** (например, `S01`, не ФИО). Код запоминается в браузере:
   второе дело создаётся с ним же, и результаты свяжутся.
2. **Загрузить материалы.** Поддерживаются DOCX, PDF (включая сканы — они
   распознаются OCR), TXT. Перетащите файлы в область загрузки.
3. **Нажать «Сформировать проект».** На этом стенде один проект на быстрой
   модели формируется примерно **3–4 минуты**. Если несколько человек нажали
   одновременно, задача встанет в очередь — статус будет «ожидает», это
   нормально, страницу закрывать не нужно.

После формирования:

- разделы проекта читаются на экране;
- у каждого утверждения виден источник (документ, страница, фрагмент);
- замечания проверки показывают, что модель выдумала или перепутала;
- жёлтая пометка «требует проверки» означает, что данных в материалах нет.
  Это правильный результат, а не сбой.

## Обратная связь

Кнопка **«★ Обратная связь»** — справа над проектом. Выберите:

- решение по проекту: принял / нужна доработка / отклонил;
- оценку 1–5;
- имя (необязательно) и комментарий.

Отзыв сохраняется в базе и дублируется в файл
`data/feedback/feedback.jsonl`. Модель подставляется автоматически — та,
что писала проект по этому делу, поэтому отзывы сильной и слабой модели
не смешиваются. Ничего дополнительно отправлять не нужно.

## Важно: персональные данные

- Для теста используйте **демонстрационное дело** или **обезличенные**
  документы.
- Не загружайте реальные материалы дел с ФИО, адресами, телефонами.
- Не вводите персональные данные в поле отзыва.

Стенд локальный, без выхода в интернет, но это тестовая сборка без
разграничения доступа: не выставляйте её в открытую сеть.

## Администратору

### Запуск и остановка

```bash
sudo systemctl status courtdraft-backend
sudo systemctl restart courtdraft-backend
sudo systemctl stop courtdraft-backend
```

Служба включена в автозапуск, после включения ВМ поднимается сама.
Ollama тоже запускается как системная служба.

Проверка состояния:

```bash
curl -s http://127.0.0.1:8081/api/health
```

Ожидаемо: `"status":"OK"`. Допустимо `DEGRADED`, если warning относится
только к Qdrant (он работает во встроенном режиме).

### Где что лежит

| Что | Путь |
|---|---|
| Проект | `/home/ubuntuii/courtdraft-ai` |
| Настройки | `/home/ubuntuii/courtdraft-ai/.env` |
| База | `/home/ubuntuii/courtdraft-ai/data/cases/courtdraft.db` |
| Отзывы (дубль) | `/home/ubuntuii/courtdraft-ai/data/feedback/feedback.jsonl` |
| Лог backend | `sudo journalctl -u courtdraft-backend -n 100` |

| Лимиты Ollama | `/etc/systemd/system/ollama.service.d/limits.conf` |

### Отзывы

Посмотреть статистику:

```bash
curl -s http://127.0.0.1:8081/api/feedback/stats
```

Выгрузить все отзывы:

```bash
curl -s http://127.0.0.1:8081/api/feedback/export
```

Резервная копия в JSONL:

```bash
cat /home/ubuntuii/courtdraft-ai/data/feedback/feedback.jsonl
```

### Переключение этапа теста

**Этап 1 — все на быстрой модели.** В `.env` должно быть:

```env
OLLAMA_MODEL=qwen2.5:1.5b
MODEL_ROUTING_ENABLED=true
STRONG_MODEL=wavecut/vikhr:7b-instruct_0.4-Q4_1
WEAK_MODEL=qwen2.5:1.5b
STRONG_MODEL_QUOTA=0
```

**Этап 2 — первым 5 делам сильная модель.** Поставьте квоту и перезапустите:

```bash
sed -i 's/^STRONG_MODEL_QUOTA=.*/STRONG_MODEL_QUOTA=5/' \
  /home/ubuntuii/courtdraft-ai/.env
sudo systemctl restart courtdraft-backend
```

Назначение фиксируется за делом: повторная генерация того же дела пойдёт
той же моделью. Слот не освобождается удалением дела — иначе квоту можно
обойти.

Проверить, как разложились отзывы:

```bash
curl -s http://127.0.0.1:8081/api/feedback/stats
```

В ответе `by_model` — отдельно `count` и `average_rating` для каждой
модели.

### Выгрузка для разбора

После занятия, когда все проекты сформированы:

```bash
cd /home/ubuntuii/courtdraft-ai/backend
PYTHONPATH=. .venv/bin/python scripts/export_learning_data.py \
  --out /home/ubuntuii/courtdraft-ai/data/learning \
  --allow-personal
```

Появятся:

- `data/learning/manifest.jsonl` — по строке на дело: код участника,
  модель, оценка, вердикт, число документов;
- `data/learning/students/<код>/<дело>/documents.jsonl` — тексты
  материалов;
- `draft.txt` — последний проект;
- `feedback.jsonl` — отзывы по этому делу.

`--allow-personal` обязателен для несинтетических дел. Без него скрипт
выгружает только синтетические и предупреждает об остальных.

### Модели

- `qwen2.5:1.5b` — быстрая: около 3–4 минут на проект, ~2,7 ГБ ОЗУ.
- `wavecut/vikhr:7b-instruct_0.4-Q4_1` — качественная: на 4 vCPU около
  20–30 минут на проект. С 4 потоками Ollama стала примерно вдвое
  быстрее, чем на двух, но prefill всё равно ~5 токенов/с.

### Если проект не формируется

1. `sudo systemctl status courtdraft-backend` — служба запущена?
2. `curl -s http://127.0.0.1:11434/api/version` — Ollama отвечает?
3. `sudo journalctl -u courtdraft-backend -n 100` — что в логе?
4. `free -m` — есть ли свободная память? При нехватке:
   `sudo systemctl restart ollama`.

### Ограничения стенда

- Qdrant работает во встроенном режиме: данные поиска не переживают
  перезапуск, проекты в SQLite сохраняются.
- Нет аутентификации и разграничения доступа.
- Смысловой фильтр инструкций в документах отключён: нет тяжёлых
  `transformers/torch`. Проверка идёт по известным формулировкам, об этом
  честно предупреждает интерфейс.
