# Тест на ВМ: памятка участнику и администратору

Адрес системы: **http://10.19.20.20:8081/app**

Это тестовый стенд. Система формирует **проект** судебного акта.
Решение принимает человек; автоматического утверждения нет.

---

## Что делать участнику (3 шага)

1. **Выбрать дело.** Слева уже есть демонстрационное дело «2-456/2025».
   Можно создать своё: «+ Создать дело» и загрузить материалы.
2. **Загрузить материалы.** Поддерживаются DOCX, PDF (включая сканы — они
   распознаются OCR), TXT. Перетащите файлы в область загрузки.
3. **Нажать «Сформировать проект».** На этом стенде один проект формируется
   примерно **3 минуты**. Если несколько человек нажали одновременно,
   задача встанет в очередь — статус будет «ожидает», это нормально,
   страницу закрывать не нужно.

После формирования:

- разделы проекта читаются на экране;
- у каждого утверждения виден источник (документ, страница, фрагмент);
- замечания проверки показывают, что модель выдумала или перепутала;
- жёлтая пометка «требует проверки» означает, что данных в материалах нет.
  Это правильный результат, а не сбой.

## Обратная связь

Кнопка **«★ Обратная связь»** — справа над проектом. Выберите:

- решение по проекту: принял / нужна доработка / отклонил;
- оценку 1–5;
- имя (необязательно) и комментарий.

Отзыв сохраняется в базе и дублируется в файл
`data/feedback/feedback.jsonl`. Ничего дополнительно отправлять не нужно.

## Важно: персональные данные

- Для теста используйте **демонстрационное дело** или **обезличенные**
  документы.
- Не загружайте реальные материалы дел с ФИО, адресами, телефонами.
- Не вводите персональные данные в поле отзыва.

Стенд локальный, без выхода в интернет, но это тестовая сборка без
разграничения доступа: не выставляйте её в открытую сеть.

## Администратору

### Запуск и остановка

```bash
sudo systemctl status courtdraft-backend
sudo systemctl restart courtdraft-backend
sudo systemctl stop courtdraft-backend
```

Служба включена в автозапуск, после включения ВМ поднимается сама.
Ollama тоже запускается как системная служба.

Проверка состояния:

```bash
curl -s http://127.0.0.1:8081/api/health
```

Ожидаемо: `"status":"OK"`. Допустимо `DEGRADED`, если warning относится
только к Qdrant (он работает во встроенном режиме).

### Отзывы

Посмотреть статистику:

```bash
curl -s http://127.0.0.1:8081/api/feedback/stats
```

Выгрузить все отзывы:

```bash
curl -s http://127.0.0.1:8081/api/feedback/export
```

Резервная копия в JSONL:

```bash
cat /home/ubuntuii/courtdraft-ai/data/feedback/feedback.jsonl
```

### Модель

На стенде стоит быстрая модель `qwen2.5:1.5b`: около 3 минут на проект,
около 2,7 ГБ ОЗУ. Этого достаточно, чтобы 20 человек прошли тест за
3 часа с очередью.

Более качественная, но медленная модель — `wavecut/vikhr:7b-instruct_0.4-Q4_1`:
примерно 1,7 токена/с на 4 ядрах, один проект может идти 30+ минут.
Переключение — только через `.env`, затем перезапуск службы:

```bash
sed -i 's#^OLLAMA_MODEL=.*#OLLAMA_MODEL=wavecut/vikhr:7b-instruct_0.4-Q4_1#' \
  /home/ubuntuii/courtdraft-ai/.env
sudo systemctl restart courtdraft-backend
```

Вернуть быструю:

```bash
sed -i 's#^OLLAMA_MODEL=.*#OLLAMA_MODEL=qwen2.5:1.5b#' \
  /home/ubuntuii/courtdraft-ai/.env
sudo systemctl restart courtdraft-backend
```

### Если проект не формируется

1. `sudo systemctl status courtdraft-backend` — служба запущена?
2. `curl -s http://127.0.0.1:11434/api/version` — Ollama отвечает?
3. `tail -50 /home/ubuntuii/backend.log` — что в логе?
4. `free -m` — есть ли свободная память? При нехватке:
   `sudo systemctl restart ollama`.

### Ограничения стенда

- Qdrant работает во встроенном режиме: данные поиска не переживают
  перезапуск, проекты в SQLite сохраняются.
- Нет аутентификации и разграничения доступа.
- Смысловой фильтр инструкций в документах отключён: нет тяжёлых
  `transformers/torch`. Проверка идёт по известным формулировкам, об этом
  честно предупреждает интерфейс.
