# Разбор расхода API: почему дашборд показывает больше локального учёта

- Дата: 2026-11-11
- Дашборд ZvenoAI: **25,59 ₽**, **418 запросов** за день
- Локальные отчёты `artifacts/**/report.json`: **291 успешный вызов**, **~4,70 ₽**
- Разница: **127 запросов**, **~20,9 ₽** не отражены локальным учётом

## Что считалось локально

| Прогон | Успешных вызовов | Локальная стоимость |
|---|---:|---:|
| 50 реальных дел | 100 | 1,4181 ₽ |
| 10 дел после исправлений | 20 | 0,2651 ₽ |
| 30 дел | 60 | 0,8847 ₽ |
| 3 краевых + 3 + 3 | 18 | 0,2293 ₽ |
| 35 block-заданий DeepSeek | 35 | 0,0995 ₽ |
| A/B baseline 15 | 29 | 0,6346 ₽ |
| A/B GraphRAG 15 | 28 | 0,3798 ₽ |
| A/B pipeline 15 | 26 | 0,6520 ₽ |
| smoke/прочее | 4 | ~0,05 ₽ |
| **Итого** | **~291** | **~4,70 ₽** |

## Почему локальный учёт не сошёлся с дашбордом

Точную причину без выгрузки дашборда назвать нельзя, но есть четыре
подтверждённых механизма:

1. **Неудачные и повторные HTTP-запросы не попадали в локальный отчёт.**
   В прогонах были десятки `All connection attempts failed` и пустых
   ответов; `TrackingProvider` записывал только успешный `_one_call`.
   Если провайдер считает попытки/повторы, они не видны в `report.json`.

2. **Локальная цена считается по `prompt_tokens + completion_tokens`.**
   Если провайдер отдельно тарифицирует reasoning/cache-токены или
   считает по другой редакции цены, локальная сумма занижается.
   В отчётах цена бралась из `/v1/models`, но не сверялась с фактическим
   счётом.

3. **Часть вызовов ушла на другую модель.** 4 вызова выбрали
   `deepseek/deepseek-v4-flash-0731` (вход 8,39 / выход 27,06 ₽ за 1M)
   вместо дешёвой `deepseek-v4.1-flash-1017` (1,16 / 29,00). Это немного,
   но модель-роутер не гарантирует одну модель на весь прогон.

4. **Слишком много прогонов с длинным контекстом.**
   50 + 30 + 10 + 3×3 + 35 block + 3×15 A/B — это больше 180 проектов
   и сотни вызовов. GraphRAG/pipeline добавили контекст: 49,6k → 63k
   токенов на 15 дел, при этом заметного выигрыша в A/B не было.

## Что сделать, чтобы не повторилось

- Вести **append-only журнал каждого HTTP-вызова**, включая ошибки:
  `artifacts/budget_ledger.jsonl` (уже добавлен в `TrackingProvider`).
- Сверять бюджет по **дашборду провайдера**, а не только по локальным
  токенам.
- Зафиксировать модель: `OPENAI_MODEL_AUTO=false` и явный
  `deepseek/deepseek-v4.1-flash-1017` на время замеров.
- Разделить ключи: приложение/eval и другие инструменты — разные ключи
  с разными лимитами.
- Не гонять 50 дел на каждый вариант. Для A/B — 10–15 дел, остальное
  локально/mock.
- GraphRAG и pipeline держать выключенными до подтверждённого A/B:
  `GRAPHRAG_ENABLED=false`, `MULTI_AGENT_ENABLED=false`.

## Что уже сделано

- `TrackingProvider` теперь пишет `ok`/`error` по каждому вызову в
  `artifacts/budget_ledger.jsonl`.
- В `cd_eval`/`eval_deepseek_quality` есть бюджетный стоп.
- GraphRAG/pipeline по умолчанию выключены.

## Ограничение

Разбор основан на локальных артефактах и скриншоте дашборда. Для точного
ответа нужна выгрузка операций из ZvenoAI: время, ключ, модель, токены,
стоимость. Тогда 127 запросов можно разложить по источникам.
