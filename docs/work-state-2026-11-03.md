## 3. Что уже работает

- **Изоляция.** Каждый участник видит только свои дела и материалы.
  Прямой доступ к чужому делу или файлу — 403. Без кода — режим
  администратора (нужен для разбора).
- **Вход по коду.** Без кода интерфейс не показывает список и не создаёт
  дела. Код переключается кнопкой в шапке (для одного компьютера на
  нескольких студентов).
- **Дела без кода не создаются** (422). Демо-дело — исключение.
- **Скрытие прежних дел.** Колонка `is_archived`, миграция архивирует всё,
  что было до неё; такие дела не видны ни в списке, ни по ссылке (404).
  Данные остаются в базе и в резервных копиях.
- **Карточка из документов.** Ручных полей нет: «Создать дело» — одно
  нажатие. Номер и суд извлекаются из шапки загруженных документов
  (`app/ingestion/case_card.py`).
- **Устойчивость загрузки.** Удаление дела во время загрузки даёт
  понятный 409, а не 500. Повтор файла — 409. Загрузка привязана к делу,
  открытому в момент выбора файлов.
- **Связь.** Обрыв на несколько секунд (перезапуск службы) переживается:
  запросы на чтение повторяются, шапка показывает «переподключение…».

## 7. Как выкладывать на стенд

Скрипт: `scripts/vm_deploy_isolation.py`. Что делает: бэкап базы →
копии заменяемых файлов → заливка → проверка импорта → миграции →
восстановление кодов → перезапуск процессом → проверка изоляции по API.

Порядок и ограничения:

1. В конфиге `D:\itотдел\opencode.json` стоит запрет `*deploy*` на
   команды агента — запуск скрипта с таким именем выполняет человек
   либо владелец снимает запрет.
2. Перезапуск убивает незавершённые проекты (задания в памяти процесса).
   Выкладывать только при остановленном тесте.
3. Перед выкладкой снимается резервная копия базы; путь печатается
   в конце. Копии файлов — в `data/cases/backups/files-<время>/`.

## 9. Ограничения, о которых нельзя забывать

- **Аутентификации нет.** Код участника — единственный ключ; кто прислал
  чужой код, увидит чужие дела. Для теста приемлемо, для эксплуатации нет.
- **Одна модель и один процесс.** Формирование идёт по одной задаче;
  при нескольких участниках — очередь, а не сбой.
- **Qdrant в режиме памяти.** Поиск по базе знаний работает в ограниченном
  виде (`MOCK` в health), это не поломка.
- **SOCKS/сеть.** Доступ с рабочей машины к стенду периодически рвётся
  (соединения висят в `syn-recv`); проверку удобнее делать с самой ВМ
  через `localhost`.
