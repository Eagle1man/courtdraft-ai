# Параметры под 7B и прогон A/B (05.11.2026)

Сейчас стенд работает на `qwen2.5:1.5b` с лимитом 420 токенов на раздел.
Для 7B эти настройки малы: модель упрётся в лимит и оборвёт
мотивировочную часть, а таймаут 120 секунд не покроет более длинную
генерацию.

## Что изменить в `.env` стенда

```ini
# модель
OLLAMA_MODEL=courtdraft-7b
OLLAMA_NUM_CTX=8192
OLLAMA_TIMEOUT_SEC=600

# генерация
DRAFT_MAX_TOKENS=1200
DRAFT_MAX_TOKENS_RETRY=1800
DRAFT_CONTEXT_CHARS=6000

# база знаний по нормам
RAG_LAWS_ENABLED=true
QDRANT_MODE=local
QDRANT_PATH=data/qdrant
EMBEDDING_PROVIDER=local
EMBEDDING_MODEL=bge-m3
```

| Параметр | Было | Стало | Почему |
|---|---|---|---|
| `OLLAMA_MODEL` | `qwen2.5:1.5b` | 7B-модель | качество связного текста |
| `OLLAMA_NUM_CTX` | 4096 | 8192 | промпт + нормы + ответ не влезают в 4k |
| `OLLAMA_TIMEOUT_SEC` | 120 | 600 | 7B на T4-классе пишет раздел дольше |
| `DRAFT_MAX_TOKENS` | 420 | 1200 | ответ в датасете медианой 6 360 знаков ≈ 1 500 токенов |
| `DRAFT_MAX_TOKENS_RETRY` | 760 | 1800 | вторая попытка с якорем длиннее |
| `DRAFT_CONTEXT_CHARS` | 4000 | 6000 | при 8k контекста можно дать больше материалов |

Значения — стартовые. Их надо подтвердить замером: если модель
обрывает ответ, поднимать `DRAFT_MAX_TOKENS`; если падает по памяти
Ollama, снижать `OLLAMA_NUM_CTX`.

## База знаний по нормам

Индекс строится один раз и лежит на диске (`QDRANT_MODE=local`), поэтому
переживает перезапуск службы.

```bash
cd /home/ubuntuii/courtdraft-ai/backend
.venv/bin/python -m scripts.build_law_index --download
```

Что делает: скачивает текст ГК РФ, разбирает на 1 713 статей, режет на
~2 700 пассажей, считает эмбеддинги `bge-m3` и кладёт в коллекцию
`legal_laws`.

Проверка без модели:

```bash
.venv/bin/python -m scripts.build_law_index --dry-run
```

Ожидаемый вывод: около 2 700 пассажей, медиана 850 знаков, четыре части
кодекса распознаны.

**Важно:** индекс и запросы должны считаться одной моделью эмбеддингов.
Если индекс построен `bge-m3`, а `EMBEDDING_PROVIDER=mock`, поиск будет
бессмысленным (векторы разной природы).

## Проверка поиска норм

Перед A/B стоит убедиться, что поиск норм вообще работает: если индекс
не находит статью, модель её не увидит.

Набор собран из триплетов: 4 205 запросов по ГК РФ, у каждого известен
номер ожидаемой статьи (`backend/data/eval/laws-retrieval-gk.jsonl`).

```bash
cd /home/ubuntuii/courtdraft-ai/backend
.venv/bin/python -m scripts.eval_law_index --top-k 5
```

Печатает recall@1/3/5 и MRR. Ориентир: на `bge-m3` recall@5 для
юридических запросов должен быть заметно выше 0,5. Если он близок к
нулю — индекс построен другой моделью эмбеддингов, чем та, что
используется при поиске.

## Порядок выкладки

1. Залить код и шаблоны (`scripts/vm_deploy_update.py`).
2. При остановленном тесте поменять `.env` (значения выше).
3. Построить индекс норм.
4. Перезапустить службу.
5. Проверить `GET /api/health` — Qdrant не должен быть `MOCK`.
6. Прогнать A/B.

## Прогон A/B

Нужны 5–7 дел с материалами, одинаковые для обоих прогонов. Id берутся
из интерфейса или `GET /api/cases`.

**Прогон 1 — текущая модель (1.5B):**

```powershell
python scripts\diagnostics\ab_collect.py --label base-1p5 ^
    --cases <id1>,<id2>,<id3>,<id4>,<id5>
```

**Переключить модель и параметры, перезапустить службу.**

**Прогон 2 — 7B:**

```powershell
python scripts\diagnostics\ab_collect.py --label tuned-7b ^
    --cases <id1>,<id2>,<id3>,<id4>,<id5>
```

**Сравнение:**

```powershell
python scripts\diagnostics\ab_compare.py ab-base-1p5.json ab-tuned-7b.json
```

Скрипт печатает по каждому делу: статус проверки, число замечаний,
утверждения без источника, длину мотивировочной части и время, плюс
средние.

## Что считать успехом

| Метрика | Целевое изменение |
|---|---|
| Пустая/короткая мотивировочная | должно исчезнуть |
| Утверждения без источника | снижение, но не до нуля |
| Замечания `JURISDICTION_MISMATCH` | ноль (уже обеспечено шаблоном) |
| Пометки выдуманных дат | ноль (обеспечено защитой) |
| Время на проект | рост допустим, но очередь важнее качества |
| Обрывы ответа на лимите токенов | ноль |

## Ограничения

- Один процесс и одна модель: 7B увеличивает очередь, а не сокращает.
- 7B без RAG выдумывает нормы правдоподобнее 1.5B — защита и база
  знаний остаются обязательными.
- A/B на пяти делах показывает направление, а не статистику. Для
  решения о выкладке нужно хотя бы 15–20 дел.
