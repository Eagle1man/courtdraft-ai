# Что изменено после живого теста (04–05.11.2026)

Переделка по итогам теста со студентами. Каждый пункт — ответ на
конкретную находку в данных теста, а не общее улучшение.

## 1. Вид судопроизводства (P0)

**Находка:** 21 из 26 проектов применял ГПК РФ к арбитражным делам.

**Причина была не в модели:** интерфейс всегда отправлял
`case_type = "civil"`, а генератор всегда брал шаблон `civil_judgment`.
Вид дела хранился, но на проект не влиял.

**Что сделано:**

- `backend/app/ingestion/jurisdiction.py` — определение типа по
  материалам: шапка «Арбитражный суд», номер «А40-…», ссылки на АПК РФ,
  суд общей юрисдикции, ГПК РФ, состав сторон. Слабые или
  противоречивые признаки — тип не меняется (угадывать нельзя).
- `data/templates/arbitration_judgment.json` — отдельный арбитражный
  шаблон: ст. 168, 170 АПК РФ, доказывание — ст. 65, 71 АПК РФ,
  госпошлина — ст. 110 АПК РФ, обжалование — ст. 181 АПК РФ.
- `backend/app/services/draft_service.py` — шаблон выбирается по
  `case.case_type`, а не жёстко.
- `backend/app/api/routes/cases.py` — при загрузке документа тип
  определяется и записывается в дело.
- `backend/app/verification/engine.py` — симметричная проверка: чужой
  кодекс в проекте (ГПК в арбитражном деле и наоборот) — замечание HIGH.
  Отрицания («нормы ГПК РФ не применяются») не считаются ошибкой.
- `backend/scripts/reclassify_jurisdiction.py` — пересчёт типа у прежних
  дел по их материалам (dry-run + применение).
- Интерфейс больше не отправляет `case_type`, показывает чип
  «арбитраж» / «гражданское».

## 2. Выдуманные даты (P0)

**Находка:** 8 из 26 проектов содержали даты, которых нет в материалах.

- `backend/app/drafting/date_guard.py` — по образцу защиты по суммам:
  дата либо есть в материалах, либо помечается в тексте и попадает в
  пробелы раздела.
- Исключение — вычисляемые даты: срок обжалования/вступления в силу,
  отсчитанный от известной даты стандартным сроком (1–90 дней) и
  стоящий рядом со словом «обжалование», «вступает», «срок», «не позднее».

## 3. Неполная мотивировочная часть (P1)

**Находка:** 9 из 26 проектов — почти пустая мотивировочная часть.

- `backend/app/drafting/section_quality.py` — `motivating_shortcoming`:
  короче 400 знаков или без ссылок на нормы → раздел помечается как
  требующий проверки, проект получает `REVIEW_REQUIRED`.
- То же проверяется при повторной верификации, а не только при генерации.

**Реквизиты резолютивной части** отдельно не добавлялись: они уже
покрыты `backend/app/verification/resol_checks.py` (госпошлина, порядок
обжалования, «с кого и в чью пользу», сроки, доли, заочное производство
и т.д.).

## 4. Пустые дела (P1)

**Находка:** до четырёх пустых дел подряд у одного участника.

- `CaseRepository.find_empty_case` — повторное «Создать дело» возвращает
  уже существующее дело без материалов вместо новой пустышки.
- Демо-дела и дела без кода не переиспользуются.
- Интерфейс различает сообщения «дело создано» и «возвращено ваше
  незаполненное дело».

## 5. Задания переживают перезапуск (P2)

**Находка:** очередь жила в памяти; за тест ~34 задания потеряны при
пяти перезапусках.

- Таблица `jobs` (миграция `d4f1a7c93b20`) — состояние задания в базе.
- `JobRepository`: создание, обновление, чтение, `mark_interrupted`.
- При старте службы незавершённые задания помечаются `FAILED` с
  причиной «служба была перезапущена — задание прервано».
- `GET /api/jobs/{id}` читает из памяти, а при её отсутствии — из базы.

## Чего сознательно не делали

- **Разделение отзыва человека и вставленного ИИ-разбора** — требует
  изменения схемы отзывов; отложено, чтобы не менять формат перед тестом.
- **Qdrant в режиме памяти** — не поломка, ограничение стенда.
- **Аутентификация** — код участника остаётся единственным ключом.

## Выкладка на стенд

Скрипт: `scripts/vm_deploy_update.py`.

```
python scripts\vm_deploy_update.py --dry-run
python scripts\vm_deploy_update.py
```

Порядок: бэкап базы и файлов → заливка архивом → проверка импорта →
`alembic upgrade head` → пересчёт вида судопроизводства → перезапуск
сигналом → проверки health, шаблона и версии интерфейса.

**Выкладывать только при остановленном тесте:** перезапуск убивает
незавершённые задания генерации. Откат — команды печатаются в конце
выкладки (копия базы и архив файлов в `data/cases/backups/`).

После выкладки участникам нужен Ctrl+F5: интерфейс обновлён до
`app.js?v=0.6.6`.
