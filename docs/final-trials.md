# Итоговые испытания (Этап 10)

Дата прогона: 2026-10-31. Машина: Windows 11, Python 3.14.3, **CPU-only,
8 ГБ RAM**, БД — SQLite. Реальные модели на этой машине не запускались
(см. ограничения).

Воспроизводимость — одна команда:

```powershell
cd D:\courtdraft-ai
backend\.venv\Scripts\python.exe scripts\final_trials.py
```

Скрипт запускает проверки, пишет `docs/final-trials.json` с фактическими
кодами возврата и выводом и печатает итог. Отчёт ниже составлен по этому
файлу, а не по памяти.

## 3. Что изменилось на этапах 7, 8, 10

- **Этап 7.** `backend/app/model_routing/`: реестр маршрутов задач
  (`SECTION_DRAFT`, `SECTION_RETRY`) и кэш ответов. По умолчанию маршрут
  совпадает с `OLLAMA_MODEL` — без явной настройки модель не подменяется.
  Кэш включается только на штатном пути (провайдер из настроек): при
  явно переданном провайдере (тесты, стенды) вызовы идут в модель, иначе
  стенд получал бы чужие ответы.
- **Этап 8.** `backend/app/verification/recheck.py` +
  `POST /api/drafts/{id}/reverify`: отчёт считается заново по последней
  сохранённой версии. Статус не переносится: ручная правка делает старый
  отчёт устаревшим (`REVIEW_REQUIRED`), новый статус появляется только из
  проверки. В интерфейсе — кнопка «Проверить заново» и пунктирная пометка
  «отчёт относится к прежней версии».
- **Этап 10.** `scripts/final_trials.py` + этот отчёт.
- **«УСТАНОВИЛ» правилами при отказе модели.** Если модель отвечает
  заголовком (обе Vikhr на этом промпте), раздел собирается из фактов
  материалов с цитатами; технический отказ модели (LLM недоступен) не
  подменяется правилами — там честный пустой раздел с пометкой.
- **Повтор после сбоя модели.** Обрыв соединения или падение процесса
  Ollama посреди раздела запускает вторую попытку с якорным промптом;
  пустой акт не остаётся, если модель жива.
- **Защита от инструкций в документах (prompt injection).**
  `app/ingestion/injection.py` ищет фразы-команды в тексте документа и
  показывает предупреждение при загрузке; материалы в промпте отделены
  границами «данные, а не задание». Текст документа при этом не
  вырезается — это доказательство.
- **Необязательный смысловой фильтр.** `app/ingestion/injection_guard.py`
  (Prompt Guard 2 86M) выключен по умолчанию; выбор модели, установка и
  план проверки на русских текстах — `docs/injection-filter-model.md`.
  Набор для оценки готов: 54 фрагмента (36 обычных, 18 попыток) в
  `backend/tests/data/injection_guard_set.jsonl`, метрики и выбор порога —
  `scripts/eval_injection_guard.py` (precision не ниже 90%).
- **Постоянный кэш ответов.** `RESPONSE_CACHE_PATH` включает SQLite-кэш:
  ответы переживают перезапуск, срок и лимит соблюдаются.
- **Проверка инфраструктуры.** `scripts/infra_check.py` показывает, что
  реально используется (SQLite/PostgreSQL) и отвечает ли Qdrant.
- **OCR сканированных PDF.** `app/ingestion/ocr.py`: если текстового
  слоя нет, страницы растеризуются PyMuPDF и распознаются Tesseract
  (`rus+eng`) локально. Текст, полученный распознаванием, помечается
  `text_source=ocr`, в интерфейсе — метка «распознано OCR», в
  предупреждениях загрузки — напоминание об ошибках OCR. Если
  распознать нельзя, загрузка называет причину, а не создаёт пустой
  документ.
- **Описательная часть — правилами.** `_build_descriptive_section`:
  стороны, предмет спора и дословные требования истца с указанием
  документа; при отсутствии требований — пометка в «Не хватает данных».
  Причина: `vikhr-7b` на этом промпте возвращает немедленный конец
  ответа (проверено на уровне API Ollama), а пересказ требований
  моделью уже приводил к подмене суммы.

## 4. Ограничения (проверено или известно, не выдумано)

1. **REAL-прогон приостановлен по решению владельца.** Все цифры выше —
   про детерминированные правила, MOCK-провайдер и механику кэша.
   Проверки REAL на этой машине (CPU, 7,8 ГБ, без видеокарты) выполнены
   ранее: `qwen2.5:1.5b` — 153,9 с, пустая мотивировочная; `vikhr-7b` —
   5–6 минут на проект, при этом одна из модельных частей может остаться
   пустой: модель отвечает заголовком либо Ollama падает по памяти
   (`docs/real-run-monday.md` §6). Выводы о качестве на RTX 3050 сделать
   нельзя. Включение REAL — по отдельной команде владельца.
2. **Этап 6 воспроизводится только при `data/demo/real/`.** Эти
   материалы вне репозитория (персональные данные и лицензия корпуса):
   на чистом клоне шаг упадёт, хотя здесь проходит.
3. **Кэш живёт в памяти процесса.** Перезапуск и второй воркер его не
   видят; TTL 1 час, 128 записей. Для локальной однопроцессной системы
   этого достаточно, для нескольких экземпляров — нет.
4. **Браузерные проверки меняют демо-БД.** Они добавляют версию проекта
   на стенде; рабочая БД не затрагивается.
5. **Playwright — в системном Python**, не в `backend/.venv`. Запуск из
   venv даёт `ModuleNotFoundError` (проверено).
6. **SQLite, не PostgreSQL; Qdrant в режиме memory.** Перенос на
   PostgreSQL этим прогоном не проверялся.
7. **Проверка утверждений — правила, не NLI.** `SUPPORTED` означает
   «число или дата найдены в документе с цитатой», а не «утверждение
   истинно». Смысловое соответствие не проверяется — это записано в
   `docs/verification-pipeline-audit.md` как открытый класс ошибок.
8. **Защита от prompt injection не реализована** — вне рамок этапов.
9. **OCR ошибается на плохих сканах.** Текст распознаётся локальным
   Tesseract; цифры и инициалы могут быть прочитаны неверно. Такой
   документ помечен `text_source=ocr`, но утверждение «источник не
   найден» иногда означает ошибку распознавания, а не отсутствие факта.
   Tesseract — внешняя программа: без неё скан отклоняется с причиной,
   а не превращается в пустой документ.
10. **Защита от prompt injection не полная.** Детектор знает известные
    формулировки (русские и английские) и показывает предупреждение;
    промпт отделяет материалы от задания. Но документ не вычищается —
    это доказательство, — а незнакомая формулировка detector не поймает.
11. **Смысловой фильтр не включён: локальные модели его не заменяют.**
    На наборе из 54 фрагментов `qwen2.5:1.5b` даёт precision 0,81–0,85
    при recall 0,94 (3–4 ложных на 36 документов), `qvikhr` — precision
    1,00 при recall 0,22. Prompt Guard 2 86M на русском ещё не проверен.
    Рабочий слой сейчас — детерминированные правила (precision 1,00,
    recall 0,44).
12. **PostgreSQL и Qdrant на этой машине не проверены:** Docker-демон не
    отвечает, compose недоступен. Проверка вынесена в `scripts/infra_check.py`
    и выполняется на ВМ; локально подтверждён только SQLite + Qdrant в
    режиме memory.
