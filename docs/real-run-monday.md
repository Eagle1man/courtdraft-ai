# REAL-прогон: что сделать в понедельник

Дата подготовки: 2026-10-31. Всё, что можно было проверить без реальной
модели, проверено и записано ниже. На машине с RTX остаётся включить
режим и запустить одну команду.

На **этом** компьютере (CPU, 7,8 ГБ ОЗУ, видеокарты нет) 7B не влезает,
но REAL-прогон на модели 1,5B уже состоялся — §6. Так что «памяти нет» —
это ограничение модели 7B здесь, а не отсутствие работающего REAL-пути.

## 1. Что должно быть на машине

| Что | Проверка | Ожидаемо |
|---|---|---|
| Драйвер NVIDIA | `nvidia-smi` | `Driver Version`, `CUDA Version` |
| Ollama | `ollama --version` | версия печатается |
| Сервер Ollama | `ollama serve` в отдельном окне | `http://127.0.0.1:11434` отвечает |
| Модель | `ollama list` | нужная модель в реестре |
| Память | свободно RAM + VRAM | модель с запасом 20% влезает в VRAM или RAM |

Модель 7B (файл ~4 ГБ) требует примерно 5,8 ГБ памяти с запасом на
контекст. Если на ВМ этого нет — preflight скажет `FAIL memory` и
**не запустит** генерацию. Варианты: взять модель меньше (`qwen3.5:4b`),
освободить память или перенести прогон.

У RTX 3050 две версии — 4 и 6 ГБ. Модель `vikhr-7b` (файл 4,0 ГБ,
с запасом 4,7 ГБ) на 4-гигабайтной карте **не поместится**, и preflight
это скажет заранее; на 6-гигабайтной — поместится при свободных 4,7 ГБ
VRAM.

## 2. Переключить режим (только `.env`, код не меняется)

```ini
APP_ENV=runtime
LLM_PROVIDER=ollama
EMBEDDING_PROVIDER=local
OLLAMA_ENABLED=true
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=vikhr-7b:latest
```

## 3. Проверить готовность

```powershell
cd D:\courtdraft-ai\backend
.venv\Scripts\python.exe -m app.llm.preflight
.venv\Scripts\python.exe -m app.llm.preflight --probe
```

`--probe` делает один короткий запрос к модели: это единственная
проверка, которая доказывает, что модель **отвечает текстом**, а не
пустым `content` (у Qwen3 ответ уходит в поле размышления).

Коды: `0` — готово, `2` — не готово (причина и подсказка в выводе).

## 4. Прогон

```powershell
cd D:\courtdraft-ai
backend\.venv\Scripts\python.exe scripts\real_run.py
```

Что произойдёт:

1. preflight с пробой;
2. копия демо-БД → `data/demo/output/real-run.db` (демо-стенд и рабочая
   БД не затрагиваются);
3. генерация проекта на реальной модели по делу `DEMO-001`
   (или `--case "<номер>"`);
4. отчёт `docs/real-run.json`: время, разделы (символы, мс, ошибки),
   статус проверки, замечания;
5. итог: `0` — прогон состоялся, `2` — не готово, `3` — генерация упала
   или раздел пуст.

Полезные ключи: `--no-probe` (не тратить время на пробу),
`--fresh` (пересоздать копию БД), `--case "2-105/2025"`.

## 5. На что смотреть в отчёте

- `sections[*].chars` — 0 символов значит «раздел не сформирован»;
- `sections[*].error` — техническая причина отказа;
- `sections[*].is_mock` — `true` в REAL-прогоне быть не должно
  (значит, провайдер не переключился);
- `sections[*].latency_ms` — фактическое время по разделам;
- `verification.status` и `issues` — сколько замечаний нашла проверка.

## 6. Что уже проверено сегодня (без модели и с моделью)

```powershell
backend\.venv\Scripts\python.exe scripts\real_run.py --no-probe
# → preflight: provider OK, ollama OK, model OK,
#   memory FAIL (модель 4.0 ГБ, свободно RAM 1.3 ГБ, видеокарты нет)
# → НЕ ГОТОВО, генерация не запускалась, код 2

backend\.venv\Scripts\python.exe scripts\real_run.py --self-test --no-probe
# → весь конвейер на заглушке: дело DEMO-001, 6 разделов, 0 пустых,
#   проверка REVIEW_REQUIRED, отчёт docs/real-run-self-test.json, код 0
```

`--self-test` проверяет то, что не зависит от модели: preflight,
копирование БД, генерацию, проверку, запись отчёта. Именно поэтому в
понедельник останется только модель, а не «сначала найдём ошибку в
обвязке».

### Проверка на реальной модели, которая влезает в эту машину

На этой машине нет видеокарты, 7,8 ГБ ОЗУ; `vikhr-7b` (4,0 ГБ, с
запасом 4,7) не помещается, а `qwen2.5:1.5b` (0,9 ГБ) — помещается.
Прогон на ней состоялся 2026-10-31:

```powershell
$env:OLLAMA_MODEL = "qwen2.5:1.5b"
backend\.venv\Scripts\python.exe scripts\real_run.py --fresh --no-probe
```

Фактический результат (`docs/real-run.json`):

```
дело DEMO-001, 153.9 с, provider ollama, model qwen2.5:1.5b
разделов 6: descriptive 977 симв. / 65.7 с, established 672 / 57.6 с,
            motivating 0 / 30.3 с, остальные — правилами;
проверка: REVIEW_REQUIRED, 10 замечаний (CRITICAL 0)
код 3 — пустой раздел: motivating («текст оборван по лимиту ответа»)
```

Что это значит:

1. **Конвейер REAL работает** на этой машине: Ollama, генерация,
   проверка, отчёт — без правок кода, только `OLLAMA_MODEL`.
2. **1,5B недостаточно** для мотивировочной части: модель упирается в
   лимит ответа, раздел остаётся пустым и честно помечается. Это
   baseline для сравнения с 7B в понедельник.
3. Пустой раздел не «прошёл незаметно»: `real_run.py` вернул код 3.

### Сколько памяти и какая модель влезет

```powershell
backend\.venv\Scripts\python.exe scripts\memory_report.py
```

Печатает свободную RAM/VRAM, топ процессов по памяти и список моделей
Ollama с пометкой «влезет / НЕ влезет» (тот же запас 20%, что и в
preflight). На этой машине фактически: свободно 2,1 ГБ, видеокарты нет,
влезают `qwen2.5:1.5b` (0,9 ГБ) и `qvikhr` 1,7B (1,2 ГБ), `vikhr-7b`
(4,0 ГБ) — нет.

## 7. Чего не делать

- Не запускать `real_run.py` на `data/demo/output/demo.db` или рабочей
  БД: прогон добавляет версию проекта.
- Не считать `--self-test` доказательством качества модели: это
  заглушка, и в отчёте это помечено.
- Не выключать preflight «чтобы пошло»: если модель не влезает в
  память, падение будет посреди генерации, а не на проверке.
- Не публиковать тексты дел: в `docs/real-run.json` их нет, и добавлять
  не нужно.
