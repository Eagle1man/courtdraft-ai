# Извлечение фактов: замеры (этап 2)

Дата: 06.11.2026. Модель `qwen2.5:1.5b` (локальная Ollama, CPU),
документы — из снимка живого теста (реальные DOCX участников).

## Режимы

| Режим | Что делает |
|---|---|
| `single` | один вызов: участники, суммы, даты, требования сразу |
| `categories` | четыре вызова по категориям; суммы дополнительно ищет Python |

## Результат по делу (7 документов, режим `categories`)

| Документ | Сумм | Дат | Участн. | Цитаты точно/норм/нет | Статус | Время |
|---|---|---|---|---|---|---|
| договор 87 | 4 | 7 | 6 | 6 / 5 / 0 | ok | 115 с |
| иск А40-284567/2024 | 5 | 2 | 3 | 3 / 2 / 0 | ok | 23 с |
| договор 145 | 2 | 4 | 2 | 3 / 0 / 0 | ok | 115 с |
| протокол заседания | 1 | 6 | 2 | 5 / 0 / 0 | ok | 125 с |

| ответ на претензию | 3 | 5 | 5 | 5 / 1 / 0 | needs_review | 123 с |

Цитаты: **26 точных, 12 после нормализации, 0 не найдено.**

## Что показали замеры

1. **Один общий вызов для 1.5B не работает.** На том же иске `single`
   дал 0 сумм, 0 участников и 2 даты; `categories` — 5 сумм, 3
   участника. Узкая задача маленькой модели заметно проще.
2. **Суммы надёжнее искать Python-ом.** Числа в исках записаны как
   «1 256 850 (Один миллион двести пятьдесят шесть тысяч восемьсот
   пятьдесят) рублей 00 копеек». 1.5B на такой формулировке возвращает
   пустой список, хотя число в тексте есть. Детерминированный поиск
   находит 4–5 сумм на документ и сам определяет вид по ближайшему
   слову («госпошлина» → costs, «неустойка» → penalty).
3. **7B в режиме `single` вернул пустой реестр** (`needs_review`) и
   работал 190 с против 32 с у 1.5B. Причина не установлена: возможно,
   схема с `$defs` или обрыв по таймауту. Для вывода «7B лучше» этого
   недостаточно — нужен отдельный аккуратный прогон.
4. **`needs_review` возникает по делу:** неразобранная дата
   («0.05% за каждый день просрочки» в поле даты) или сумма. Это
   ожидаемое поведение: непонятное значение не подменяется.

## Ограничения замера

- Один прогон, одна модель, 7 документов — не статистика.
- Эталона (gold-набора) нет: сколько фактов *должно* быть, неизвестно,
  поэтому precision/recall не считаются (этап 8).
- Время — на этой машине (CPU), не на стенде.

## Вывод

Архитектура «Python находит и проверяет, модель понимает» подтверждена:
суммы и цитаты стали извлекаться там, где модель одна не справлялась.
Следующий шаг — gold-набор и метрики, иначе улучшения нечем сравнивать.
